PROMPT 1 — Diseño general del proyecto
CONTEXTO:
Estoy practicando HTML, CSS y JavaScript puro (sin frameworks). Nivel: principiante avanzado.

OBJETIVO:
Construir una aplicación web estática para una agencia de branding llamada "Colorfly Studio". La app debe ser un generador de paletas de colores funcional, dinámico, accesible y con una interfaz limpia basada en diseño profesional (siguiendo semántica HTML y buenas prácticas de CSS).

INSTRUCCIONES:

Crea una estructura de HTML semántico que incluya un encabezado con el branding de la agencia, una sección de controles (selector de tamaño de paleta y botón de generación) y un contenedor principal para las tarjetas de colores.

Implementa la lógica en JavaScript vanilla para cambiar dinámicamente el tamaño de la paleta (soportando configuraciones de 6, 8 y 9 colores) y generar valores de color aleatorios tanto en formato HEX como HSL.

Desarrolla componentes de microfeedback interactivos: un sistema de copiado al portapapeles que active un "toast" de confirmación y un "tooltip" al pasar el cursor sobre cada color. Asegura la accesibilidad básica (contraste de texto sobre el color de fondo, atributos aria-label en botones y navegabilidad por teclado).

RESTRICCIONES:

Sólo HTML, CSS y JavaScript puro.

No utilizar librerías externas para los componentes de UI (los toasts, tooltips y selectores deben crearse desde cero con CSS y JS nativo).

Estricto cumplimiento de estándares de accesibilidad WCAG (asegurar que los textos informativos de cada color sigan las reglas de contraste sobre fondos claros/oscuros).

PROMPT 2 — Algoritmo de generación de paletas
CONTEXTO:
Estoy practicando JavaScript puro (sin frameworks). Nivel: principiante avanzado.

OBJETIVO:
Desarrollar un algoritmo en JavaScript nativo para generar paletas de colores aleatorias pero visualmente armónicas, evitando que el resultado parezca ruido caótico o que los tonos sean demasiado similares entre sí.

INSTRUCCIONES:

Divide el círculo cromático (0-360 grados del tono HSL) en segmentos iguales basados en la cantidad de colores seleccionada para la paleta.

Aplica una lógica de "jitter" (desviación aleatoria controlada) dentro de cada segmento para que los colores tengan dinamismo sin perder la distribución armónica.

Acota los rangos de saturación (entre 35% y 85%) y de luminosidad (entre 28% y 68%) para garantizar que los colores generados sean estéticos y útiles para diseño de branding.

RESTRICCIONES:

Sólo HTML, CSS o JavaScript puro.

El algoritmo debe calcularse matemáticamente de forma nativa sin depender de generadores o paletas predefinidas de librerías externas.

Mantener la legibilidad del código utilizando constantes descriptivas para los límites de los rangos.

Sin explicaciones ni comentarios fuera del código.

PROMPT 3 — Conversión HSL a HEX
CONTEXTO:
Estoy practicando HTML, CSS y JavaScript puro (sin frameworks). Nivel: principiante avanzado.

OBJETIVO:
Crear una función matemática de conversión en JavaScript que transforme valores del espacio de color HSL (Hue: 0-360, Saturation: 0-100, Lightness: 0-100) a su equivalente en formato de cadena HEX de seis dígitos (#RRGGBB).

INSTRUCCIONES:

Implementa la fórmula matemática de conversión HSL a RGB utilizando una función auxiliar para procesar cada canal de color de manera limpia.

Transforma los valores numéricos resultantes de los canales RGB a base hexadecimal.

Utiliza métodos nativos de cadenas para asegurar que cada canal mantenga siempre dos dígitos (añadiendo ceros a la izquierda si es necesario) antes de concatenar el string final con el prefijo #.

RESTRICCIONES:

Sólo HTML, CSS y JavaScript puro.

Prohibido el uso de librerías de manipulación de color externas (como Chroma.js o TinyColor).

La función debe recibir parámetros numéricos limpios y retornar exclusivamente un string HEX válido.

PROMPT 4 — Accesibilidad y semántica HTML
CONTEXTO:
Estoy practicando HTML, CSS y JavaScript puro (sin frameworks). Nivel: principiante avanzado.

OBJETIVO:
Diseñar y maquetar selectores de tamaño de paleta que visualmente parezcan botones estilo "pills" interactivos, asegurando que mantengan una semántica perfecta, accesibilidad nativa por teclado y cumplimiento de las pautas WCAG.

INSTRUCCIONES:

Estructura el HTML utilizando etiquetas de formulario adecuadas (<fieldset> y <legend>) para agrupar semánticamente las opciones de tamaño.

Enmascara los elementos <input type="radio"> nativos mediante CSS de forma accesible (sin usar display: none que rompa la navegación por teclado) y envuélvelos en etiquetas <label> para controlar el diseño visual del "pill".

Implementa los estilos CSS para el estado seleccionado (:checked) y añade un indicador visual de enfoque altamente visible mediante la pseudo-clase :focus-visible para los usuarios que navegan con el tabulador.

RESTRICCIONES:

Sólo HTML, CSS y JavaScript puro.

Toda la lógica visual de selección, estados y accesibilidad de los "pills" debe resolverse exclusivamente con HTML y CSS, sin intervención de scripts de JavaScript.

Mantener el contraste del texto sobre el fondo del "pill" según los estándares WCAG AA.

PROMPT 5 — Animaciones y microfeedback
CONTEXTO:
Estoy practicando HTML, CSS y JavaScript puro (sin frameworks). Nivel: principiante avanzado.

OBJETIVO:
Implementar transiciones visuales interactivas y componentes de feedback al usuario para mejorar la experiencia de navegación en la app, incluyendo cargas fluidas de elementos y respuestas a las acciones de clic.

INSTRUCCIONES:

Desarrolla una animación CSS con @keyframes que controle la opacidad, la traslación y la escala de las tarjetas de color, aplicándoles un desfase de tiempo escalonado (animation-delay) basado en su posición en el DOM.

Crea un componente "toast" flotante oculto por defecto que se active añadiendo una clase CSS mediante JavaScript al copiar un color, utilizando temporizadores nativos (setTimeout) para retirarlo automáticamente.

Configura un "tooltip" contextual sobre cada tarjeta que cambie su estado de texto al interactuar y regrese a su estado original de forma limpia tras finalizar la acción.

RESTRICCIONES:

Sólo HTML, CSS y JavaScript puro.

No se permite el uso de librerías de animación (como Animate.css o GSAP) ni componentes de feedback de terceros.

El manejo del DOM para añadir o quitar clases debe ser directo y eficiente, limpiando correctamente los temporizadores para evitar problemas de rendimiento.
